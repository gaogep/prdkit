# PRD 撰写规范（业务上下文 + 文档模板）

本文定义 **业务领域约束** 与 **PRD 文档撰写规范**。界面与原型见 `reference/design-spec.md`（`prdkit path reference/design-spec.md`）。

---

## 1. 负责的系统矩阵

当前 PRD 需求均围绕以下三大核心系统展开或交互：

- **业务后台**
- **催收后台**
- **质检后台**

---

## 2. 需求类型与交付标准

AI 在撰写和输出 PRD 时，必须根据需求类型提供对应的结构和图表（使用 Mermaid 语法，并在 `.memory` / HTML 对应章节中体现）：

| 需求类型 | 必备交付 |
|----------|----------|
| **全链路需求**（前端+后台逻辑） | 页面原型描述、业务逻辑流程图 (Flowchart)、时序图 (Sequence Diagram) |
| **纯后台逻辑需求** | 状态机图 (State Diagram)、活动图 (Activity Diagram)、规则文字说明 |
| **纯页面改动需求** | 交互逻辑、字段校验规则、页面原型描述 |
| **纯 API 对接需求** | 系统间时序图、字段映射表、异常与重试机制 |

---

## 3. PRD 章节目录（`.memory/prd_index.md` 骨架）

AI 须按下列结构生成 `prd_index.md` 并驱动 `prd-create` 分步交付：

1. **需求背景**：业务背景、目标用户、需求价值（对应完整文档 §1 项目背景）。
2. **功能架构**：表格展示主功能、子功能等。
3. **功能说明**：按功能点拆分，可为多级子目录。

完整 Markdown 文档另含文首元信息表、修改记录、§1～§14、附录（见 §6 模板）。

---

## 4. 使用说明（给 Agent）

1. `prd-init` / `prd-clarify` / `prd-create` 执行前：`prdkit path reference/prd-writing-spec.md` → **Read** 全文。
2. 占位符 `{…}` 从 `.memory/product_brief.md`、澄清结果及用户上下文填充；文首表无法推断用 `{待填写}`。
3. **HTML 单页**（`prd-create`）分步：**需求背景** → **功能架构** → **功能说明**（逐功能）；§14、附录可在终稿轮次写入。
4. `.memory/prd_index.md` 勾选项与 §3 及撰写进度一致。
5. 全文 **极简白话**；图表类型遵循 §2；正文生成遵循 §5。

---

## 5. 内容生成规则

- **有信息则生成实质内容**：根据用户提供的上下文，尽可能生成具体、有实质内容的初稿。
- **信息不足则标注 [TODO]**：对于用户未提供足够信息的部分，用 `[TODO: 具体需要补充什么]` 标注，而不是编造内容。
- **结构化优先**：表格、列表、Mermaid 图表优先于大段叙述。
- **图表使用 Mermaid**：架构图、流程图、状态机、ER 模型等全部使用 Mermaid 代码块生成，不使用 ASCII 伪图。

## 6. 文档模板（复制骨架撰写）

```markdown
# {产品/项目/功能名称} PRD

| PRD 审核人 | {待填写} |
| --- | --- |
| 重要性 | {高/中/低} |
| 紧迫性 | {高/中/低} |
| 需求方 | {从上下文推断或标注待填写} |
| PRD 编写人 | {用户姓名或待填写} |
| PRD 提交日期 | {当前日期} |

## PRD 修改记录

| 变更时间 | 变更内容 | 变更提出部门与理由 | 修改人 | 审核人 | 版本号 |
| --- | --- | --- | --- | --- | --- |
| {当前日期} | 初始版本 | — | {编写人} | {待填写} | v1.0 |

---

## 1、项目背景
...（各章节内容）

## 14、待决事项
...

---

## 附：待完善清单
...
```

## 7. 元信息表与修改记录

| 字段 | 规则 |
|------|------|
| PRD 审核人 | 用户未提供则 `{待填写}` |
| 重要性 / 紧迫性 | 根据 brief 与澄清结论填 `{高/中/低}`，无法判断则 `{待填写}` |
| 需求方 | 业务部门或系统归属方 |
| PRD 编写人 | 用户自称或会话姓名；否则 `{待填写}` |
| PRD 提交日期 | 撰写当日 `YYYY-MM-DD` |

- **首次 `prd-create`**：可在 HTML 说明区保留一行「初始版本」`v1.0`（可选）。
- **`prd-modify`**：**禁止**在 HTML 内追加或更新「PRD 修改记录」表；变更仅写入 `.memory/modify_logs/YYYY-MM-DD_*.md`（见 `prd-modify` Skill）。

## 8. 章节撰写要点

### §1 项目背景

须覆盖：**为什么要做**、**解决什么问题**、**目标用户**、**需求价值**（与 §3「需求背景」一致）。

### §2～§13（中间章节）

按 `prd_index.md` 展开；常见含功能架构表、分功能说明、流程与状态、字段与校验、权限、接口、非功能与验收。信息不足用 `[TODO: …]`，**禁止编造**；在 **附：待完善清单** 汇总 `[TODO]` 与 `{待填写}`。

### §14 待决事项

格式建议：**事项 | 可选方案 | 决策人 | 目标日期**。

### 附：待完善清单

汇总 `[TODO: …]`、`{待填写}`、待补充 Mermaid/接口文档等。

---

## 9. 与 prdkit 工作流对照

| 本文档 | `.memory/prd_index.md` | HTML 三栏（prd-create 分步） |
|--------|------------------------|------------------------------|
| 文首元信息表 + 修改记录 | 可选记入 brief 或 PRD 首页 | 首屏或右栏说明区顶部 |
| §1 项目背景 | `需求背景` | 第一步 → `prdkit-html` 合并 → 通知「已完成需求背景的撰写。」→ **自动续写** |
| 功能架构相关 | `功能架构` | 第二步 → 同上模式 |
| 分功能说明 | `功能说明` 各子项 | 逐步 → 通知「功能XXX已完成撰写。」→ **自动下一功能** |
| §14 + 附录 | index 末级可勾选 | 全部功能完成后 |
